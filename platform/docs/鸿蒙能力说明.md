# GuardianHub 鸿蒙能力说明

> 工程路径：`platform/harmony`  
> 技术栈：HarmonyOS 6 + ArkTS Stage 模型  
> 产物：可安装调试 HAP（模拟器已验证四模块闭环）

---

## 1. 总体定位

GuardianHub 鸿蒙端不是 WebView 套壳，而是 ArkTS 原生客户端。它把「分享前 / 提交前 / 点击前 / 上传前」四个安全节点收敛到一个手机入口，并与本机或私有 FastAPI 检测服务联调。

设计原则：

- **本地优先、联网可选**：默认本机 OCR / 规则可跑；仅用户主动选择「联网增强」时调用 Qwen（图像）或 DeepSeek（代码）。
- **系统能力闭环**：选文件 → 受限读取 → 检测解释 → 处置 → 落盘 / 分享，尽量走鸿蒙系统 Kit。
- **结果可解释**：统一风险等级、0–100 评分、命中证据与处置建议。

## 2. 系统 Kit 与能力映射

| 鸿蒙能力 | 模块 | 具体用途 |
| --- | --- | --- |
| Media Library Kit / 文件与相册 Picker | Privacy Sentinel、Link Guard | 从手机文件或系统相册选择待检测图片 / 二维码 |
| 系统 Document / File Picker | Code Guardian、Doc Shield | 选择 ZIP 项目包；多选 PDF / DOCX / TXT / Markdown 等材料 |
| File Kit（受限只读） | 四模块上传链路 | 对 Picker 授权 URI 做受限读取，再以内存 multipart 上传，避免越权访问 |
| Network Kit | 四模块 API | 请求私有检测服务；手机模拟器经 `10.0.2.2` 访问开发机 |
| ArkData Preferences | 首页、历史页与各模块 | 本机持久化最多 100 条完整检测报告；支持筛选、详情、删除、清空和处置状态回写 |
| 系统相册保存 | Privacy Sentinel | 将脱敏后的安全图片写入系统相册 |
| Share Kit | 分享路径安全闸门 | 双向：既能作为**系统分享面板的目标**接收待分享的图片 / 文档 / 链接 / 文本，也能在安检后**继续分享**（安全图片、已检文件、链接、代码） |
| Share Kit（能力声明） | 分享路径安全闸门 | 在 `module.json5` 中注册 `ShareCheckAbility`，声明 `ohos.want.action.sendData` 与 `ohos.want.action.sendMultipleData` 两个动作、**12 类 UTD**（image / jpeg / png / pdf / doc / docx / text / plain-text / hyperlink / file / archive / zip-archive），使 GuardianHub 出现在系统分享面板中；未识别的文件类型也会兜给通用文件扫描 |

可选扩展（规划中，未作为当前必选演示项）：Scan Kit 扫码直达 Link Guard；分布式多端（手机选图、平板出报告）。

## 4. 各模块中的鸿蒙特性体现

### 4.1 Privacy Sentinel（隐私哨兵）

- 从手机文件选图（主路径），也可选系统相册，或加载内置演示图。
- 支持 **本地优先 / 联网增强**：联网时走 hybrid（本地 OCR/二维码 + Qwen）。
- 检测后生成安全预览，可 **保存到系统相册**，并经 **Share Kit** 分享。
- 强调闭环：识别 → 解释 → 脱敏 → 落盘 / 分享，均在鸿蒙端可完成。
- **同时是分享路径闸门的图片通道**：在系统分享面板选中 GuardianHub 后，图片先完成
  OCR + 二维码检测，再决定「分享安全图片」或「仍分享原图」。
- 后端 OCR 使用 `rapidocr` 3.x（`RapidOCROutput` 属性式结果），已由回归测试锁定契约。

### 4.2 Code Guardian（代码卫士）

- 代码片段可走服务端本地规则，或 **DeepSeek 联网增强**。
- ZIP 经系统文件选择器选取；服务端内存只读扫描、不执行代码。
- 即使选择联网增强，**也不会把整个 ZIP 外发给大模型**，保护课程 / 竞赛源码。

### 4.3 Link Guard（链接卫士）

- URL 与来源场景纯静态检查，**不主动访问目标地址**。
- 可通过系统相册选择二维码图片，在链路中完成解析与填入。

### 4.4 Doc Shield（提交护盾）

- 系统多文件选择器一次提交多份材料。
- 对照提交要求检查格式、完整性、命名与隐私风险。
- **同时是分享路径闸门的文档通道**：分享 PDF / DOCX / TXT / Markdown 时，端侧
  `ThreatScanner` 在**完全离线**状态下完成真实字节扫描（PE / PDF / ZIP / 宏 / 熵 / IoC /
  哈希黑名单），不经网络、不落盘、不执行代码。

## 5. 分享路径安全闸门（Share-Path Gate）

### 5.1 机制

GuardianHub 在 `module.json5` 中注册了一个 `exported` 的 `ShareCheckAbility`，声明
`ohos.want.action.sendData` 与 `ohos.want.action.sendMultipleData` 两个动作、共 12 类 UTD。
因此它**出现在系统分享面板里**：用户在微信、相册、文件管理器中点击「分享」时，
可以直接选择「GuardianHub 隐私安检」。

内容不会先离开设备，而是先经过检测，再由用户决定是否继续分享——这把四大模块的能力从
「进 App 检测」上移到了**分享路径上**。

### 5.2 四条内容通道

| 通道 | 分派依据 | 检测位置 | 处置与续接 |
| --- | --- | --- | --- |
| 图片 | UTD `general.image` 或 png/jpg/webp/bmp/gif 后缀 | 后端 OCR + 二维码 | 三种打码方式生成安全图片，可**分享安全图片**或**仍分享原图** |
| 文档 | UTD pdf/word 或 pdf/docx/txt/md 后缀 | **纯端侧** `ThreatScanner` | 可**继续分享文件**（源 URI 不可分享时回退沙箱副本） |
| 链接 | 文本以 `http(s)://` 开头或内嵌 URL | 后端静态检查 | 可**继续分享链接**（以 hyperlink 记录分享） |
| 代码 | 文本命中代码特征（关键字 / 赋值 / 换行 / 行注释） | **纯端侧** `LocalRuleEngine` | 可**继续分享代码**（以 `general.source-code` 分享） |

分派顺序：文件优先按 UTD，再按扩展名兜底；文本先判 URL（链接优先于代码，避免把含链接的
脚本当代码处理），再判代码特征。

### 5.3 决策点与离线降级

- 检测完成后统一展示「**是否继续分享**」区块，按钮文案随风险等级变化：低风险为「继续分享」，
  中 / 高风险为「已知晓风险，仍继续分享」，避免一键误分享。
- 分享检测完成后先写入带 `[分享拦截]` 前缀的报告；用户发起续接分享后，再回写具体动作与处置状态，可在历史页追溯。
- **离线降级**：文件、链接、代码三条通道在后端不可达时**自动改用端侧规则引擎**
  （`ThreatScanner` / `LocalRuleEngine`）并继续给出报告；报告首行明确标注
  「检测服务不可达，已改用端侧离线检测（原因）」，历史记录状态标为「端侧离线检测」。
  降级结果的覆盖范围小于联网检测，界面会提示人工复核——**不会伪装成完整检测**。
- **依赖后端的部分**：图片通道的 OCR / 二维码识别，以及链接的域名信誉与跳转链路分析。
  图片通道在服务不可达时显示「检测服务不可达，已暂停安检」并提供重试。

### 5.4 边界（如实说明）

- 这是**并列的分享目标**，不是拦截他人分享的中间人：HarmonyOS 未开放拦截并改写其他应用
  分享行为的能力，因此 GuardianHub 无法得知用户原本想发给谁，也无法自动放行到原目标。
- 续接时由用户**重新选择**分享对象，且分享的是**已脱敏 / 已检视**的内容。

## 6. 网络与隐私约定（鸿蒙侧）

- 联调默认 API：`http://10.0.2.2:8001`（模拟器经 `10.0.2.2` 访问宿主机；与
  `GuardianApi.API_BASE_URL` 保持一致）。PC Web 默认指向 `127.0.0.1:8000`——两端地址分离是
  **有意设计**：HAP 提交后评委端无法访问开发机本地后端，需要独立公网服务；Web 端由构建期注入地址。
  同时联调时让后端同时监听 8000 与 8001。
- **出提交版 HAP 前必须更换地址**：`API_BASE_URL` 在编译期写入 HAP，`10.0.2.2` 仅模拟器可解析，
  真机上完全不可用。需替换为已部署后端的公网 HTTPS 地址后重新构建。否则评委端：
  **图片通道**因依赖服务端 OCR 而不可用；**文件、链接、代码通道**会自动降级到端侧离线检测
  （链接的域名信誉与代码的深度分析能力会相应减弱，但基本风险仍可识别）。
- 真机需改为同一局域网可达的 HTTPS / 内网地址，勿使用 `localhost`。
- 链接检查始终静态、不访问目标 URL。
- 图片与代码仅在用户显式选择「联网增强」且服务端已配置密钥时，才将有限内容送往外部模型；失败自动回退本地结果。

---

## 7. 一句话总结

GuardianHub 在鸿蒙上用 **系统分享面板（Share Kit 双向）、系统 Picker、File Kit 受限读取、
Network Kit、ArkData 本地历史、相册保存**，把高校高频风险动作做成**分享路径上的操作前安全闸门**；
AI（Qwen / DeepSeek）是可选增强，不是强制上云依赖。
