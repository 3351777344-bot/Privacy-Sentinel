## 发现的问题与改进

最高优先级问题是“本地”语义与真实数据流不一致。图片和代码页默认 online，分享页先解析二维码后仍调用后端，文档页本地扫描后自动请求远程复核；Web 的本地模式也会把文件发到服务器。

本次将鸿蒙图片与代码页默认设为 hybrid，分享图片、链接和代码默认执行端侧流程，文档页默认不再调用后端。新增单独的增强入口和逐次授权弹窗。GuardianApi 在创建 HTTP 请求前要求确认，并提示目的地址、文件数量、字节数和原内容上传风险。拒绝授权不会发送；网络失败不自动重试。

付款码及登录、身份凭证 URL 增加高风险分类与隐藏内容，图片页和分享页阻止此类二维码原图增强上传。图像未识别出二维码时仍明确提示没有执行端侧 OCR，不能把未命中当作安全结论。二维码误识别和漏识别风险仍然存在。

ShareCheckAbility 不再输出完整 Want、URI 数组和前100字原文。新增 PrivacyLogger，仅接收计数及布尔状态；EntryAbility 不再输出异常对象。代码示例里的 console.log 是待检测样本，不是应用运行日志。

Web 增加所有分析与处理 POST 的逐次确认，并把“材料仅在本机分析”改为“私有后端规则”。后端模型接口要求 X-Guardian-Consent: explicit，代码修复错误不再返回底层异常文本。后端引擎提示也改为“已上传到后端，未发送给外部模型”。该请求头是声明，不是账号认证或用户点击的密码学证明。

签名配置中的明文密码、签名材料路径和固定本机路径已从当前受跟踪文件删除。新增无密码模板及本地配置忽略规则。Git历史仍保留旧配置，发现相关历史提交包括363b88d、166abe7；本次未重写远端历史，也未吊销或轮换证书。常见密钥特征扫描未发现其他匹配，但不是完整秘密审计。

三个基线测试失败来自用例在模拟配置注入前依赖本机Qwen设置；删除环境依赖断言后仍保留开关和密钥组合断言，未弱化核心行为检查。

## 数据流与情报库验收

| 内容 | 默认处理与来源 | 增强及限制 |
| --- | --- | --- |
| 图片 | 端侧二维码 未上传 | 授权后上传原图OCR 凭证码阻断 |
| 链接 | 端侧静态规则 未上传 | 未覆盖实时信誉及实际跳转 |
| 代码 | 端侧危险API与凭据规则 | 授权代码增强可调用模型 |
| ZIP | 端侧结构和威胁扫描 | 增强上传整包 非最小化摘要 |
| 文档 | 端侧结构 宏 脚本 命名规则 | 授权后上传材料做完整复核 |
| 信誉查询 | 默认关闭 | 仅哈希和风险等级 不发送原名或URL |
| PC Web | 后端演示端 | 每次上传确认 无浏览器完整离线引擎 |

情报库新增Ed25519验证基础。后端校验签名、单调版本、时效、SHA256格式和来源，先验证再原子安装并保存上一版。错误更新保留尚有效的进程缓存，过期降级为测试规则和unknown。当前实现的是SHA256情报，不包含生产域名、URL或包名情报供应链。

端侧新增固定公钥校验、完整签名包存储、重载校验、过期降级、版本防重放和显式回滚方法。当前可信公钥为空，因此拒绝生产更新；没有伪造生产情报。内置EICAR明确标记为测试规则。后端与端侧签名载荷格式不同，详见部署配置说明；生产签发工具与设备验证尚未完成。

仍需优化：统一六级风险状态目前未完成，现有主要模型仍是高、中、低；unknown通过说明和威胁判定体现。分享多文件只检测第一个并提示，尚未完成整批统一结果。代码ZIP增强仍上传完整文件，不是摘要；上传提示只有外层文件数与字节数，不提供压缩包内文件数量。历史搜索、个人策略及误报反馈未纳入本次实现。

## 发布条件与剩余风险

正式发布阻塞一：签名凭据曾进入历史。必须由持有人轮换密码及必要证书，提供新的本地签名配置。当前HAP为未签名debug包，不能作为正式签名参赛包。发布脚本要求HTTPS源地址及本地签名文件，构建后恢复受跟踪配置。

正式发布阻塞二：HDC list targets返回Empty。图库分享、真实扫码、文件权限、授权弹窗、断网、拒绝授权、重复分享、多文件、超大文件、无扩展名、敏感URI等场景尚未完成设备回归。编译成功和Node运行端侧逻辑不能代替设备证据。

正式发布阻塞三：当前没有部署真实HTTPS后端。开发服务缺少完整认证、访问隔离和网关限流，不适合直接公开；上传留存与历史访问需要正式部署审计。本轮不进行外部部署、密钥操作、公开上传或赛事提交。

正式发布阻塞四：未录制最终版本视频、未取得团队身份与权属证据。submission包含说明、功能清单、架构图、数据流、演示脚本、检查清单和调试产物；原创声明仅是待填写清单，没有代替团队签署。

其他限制：未验证真实模型识别率与误报率；自动化测试使用合成样本，不能推导真实威胁检出率。签名库生产来源和公钥未配置，缺少线上请求限流与正式发布工具。鸿蒙构建存在showDialog弃用、部分SDK调用异常处理提示及未配置签名警告；后端存在Starlette/httpx弃用警告，未把警告隐藏为零。

建议顺序：先轮换凭据并准备真机，再配置正式服务和发布签名，完成全部分享回归与抓包确认，最后录制视频、确认权属并更新材料和哈希。P2的SBOM、依赖漏洞、组织策略和多设备同步按原方案留在后续产品化阶段。
