# 部署配置说明

## 开发端口

API http://127.0.0.1:8001，Web http://127.0.0.1:5174。使用 scripts/start-alongside-hekgemi.ps1；8000 和 5173 保留给 HekGemi。启动脚本只在端口未占用时启动服务。

Web 使用 VITE_API_BASE_URL，默认 8001。鸿蒙统一使用 services/ApiConfig.ets，开发值 http://10.0.2.2:8001 仅用于模拟器；真实设备需要可达地址。发布脚本要求 GUARDIANHUB_API_BASE_URL 为 HTTPS origin，并临时注入后恢复源码。

## 签名与发布

受跟踪 build-profile.json5 不含签名材料。build-profile.example.json5 是无密码模板；本地 build-profile.local.json5 被忽略。发布构建要求该本地文件与 HTTPS 地址同时存在。真实密钥、证书和签名密码不进入 Git。

历史签名配置存在于提交 363b88d 和 166abe7 等版本中。当前清理不能撤销历史泄露，发布前由凭据持有人轮换；本次未操作开发者账号、证书吊销或远端历史。

## 情报更新

后端 modules/doc_shield/signed_feed.py 提供 Ed25519 验签、递增版本、有效期、条目校验和同目录原子替换，保留 previous.json。运营方固定 GUARDIANHUB_FEED_PUBLIC_KEY 为原始 32 字节公钥的 Base64。有效文件放置 data/threat_feed.signed.json，旧的未签名 CSV 不再自动信任。失败保留有效缓存，过期退回测试规则及 unknown。

后端签名覆盖 payload 的 UTF-8 JSON（键排序，紧凑分隔，不转义非 ASCII）。payload 含 version、updated_at、expires_at、entries；条目含 indicator、indicator_type=sha256、verdict、confidence 和 source。当前仅实现 SHA256 情报，未接入真实生产供应商。

端侧 SignedFeedVerifier 固定 DER SubjectPublicKeyInfo 格式 Ed25519 公钥，当前为空，故生产更新默认关闭。签名覆盖 version 换行 expiresAt 换行 CSV 的 UTF-8 字节。与后端 JSON 格式不同，发布工具需分别签名。SignatureDB 存储单个签名包，重载验签、到期降级，安装保留旧包并提供显式 rollback。密码学真机运行和断电持久化仍待验证。

## 服务边界

当前后端仍是开发服务：没有完整账号鉴权、租户隔离和网关级限流，不能直接暴露公网。X-Guardian-Consent 是客户端授权声明，不是身份凭据，也不能证明真人已点击。公开部署需补充认证、访问控制、上传留存审计与速率限制。
